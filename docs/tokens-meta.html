Token da Meta em 6 Passos

No fim você tem duas coisas, e só elas: INSTAGRAM_USER_ID e INSTAGRAM_ACCESS_TOKEN. Uns 15 minutos, se nada travar.

fluxo: API com Login do Instagram sem Página do Facebook sem Análise do App
O que você NÃO precisa. Página do Facebook, portfólio empresarial verificado, Análise do App, webhooks, URL de redirecionamento. Tudo isso só existe para apps que atendem contas de terceiros. Publicar na própria conta roda em Standard Access, que é o padrão de qualquer app novo. Se o painel mostrar esses cards como pendentes, ignore.
0

Antes de abrir o painel

Três pré-requisitos. Se algum falhar, o botão de gerar token simplesmente não aparece — e é aí que a maioria trava.

  1. A conta precisa ser profissional. No app do Instagram: Configurações → Tipo de conta e ferramentas → Mudar para conta profissional. Conta pessoal não é aceita por nenhuma API oficial.
  2. A conta precisa estar pública. A documentação exige isso na hora de atribuir a conta ao app.
  3. Você precisa estar registrado como desenvolvedor. developers.facebook.com → Começar. Formulário curto com confirmação de e-mail.
Empresa ou Criador? Para a API dá no mesmo. Para a @jamesolaya.es recomendo Empresa: dá botões de ação no perfil, categorias de negócio e integração com o Business Suite e a conta de anúncios. Criador tem biblioteca de música maior, mas isso não vale aqui — post publicado por API sobe com o áudio já dentro do MP4.
1

Criar o app

developers.facebook.com/apps → Criar app

O assistente tem quatro telas:

TelaO que escolher
Detalhes do appNome jamesolaya-es-publisher e um e-mail. O nome é interno, ninguém vê.
Caso de usoOutro. As opções prontas levam a fluxos com webhooks que você não vai usar.
Tipo de appEmpresa. Obrigatório.
Portfólio empresarialDeixe em branco / "Não conectar agora".
Esta é a escolha que não tem volta. Se o tipo do app não for Empresa, o card do Instagram nem aparece na lista de produtos — e o tipo não muda depois. Só criando outro app.
Se o botão recusar: existe limite de 15 apps por pessoa, e apps arquivados contam. Remova algum antigo.
2

Adicionar o produto Instagram

No painel do app, na lista de produtos

  1. Role até o card Instagram — a descrição diz "permite que criadores de conteúdo e empresas gerenciem mensagens e comentários, publiquem conteúdo…".
  2. Clique em Configurar.
Se a tela oferecer escolher entre duas APIs, pegue a API com login do Instagram, não a com login do Facebook. A segunda exige Página do Facebook vinculada e muda o host de graph.instagram.com para graph.facebook.com — o código do projeto usa o primeiro.
3

Conectar a conta e gerar o token

Instagram → Configuração da API com login do Instagram → seção "2. Gerar tokens de acesso"

Faça este passo numa janela anônima. O pop-up de login reusa a sessão do Instagram que já estiver aberta, sem avisar. Se houver outra conta logada — pessoal, antiga, de outro projeto — é ela que vai para a Meta, e você só descobre no Passo 4, com o token errado na mão. Abra anônima, entre em instagram.com só com a @jamesolaya.es, e faça tudo nessa mesma janela.
  1. Adicionar conta → o pop-up do Instagram abre.
  2. Faça login como @jamesolaya.es. Confira o @ na tela de consentimento antes de continuar.
  3. Permitir.
  4. A conta aparece numa lista. Clique em Gerar token ao lado dela.
  5. Confirme e copie o token. Ele só é mostrado uma vez — mas se perder, é só gerar outro, não quebra nada.
Esse token já é de longa duração: vale 60 dias. É a diferença entre o token do painel e o do fluxo OAuth, que expira em 1 hora. Por isso o projeto não implementa OAuth — para publicar na própria conta ele é desnecessário.

As permissões que aparecem

  • instagram_business_basic — ler perfil e mídia. Obrigatória.
  • instagram_business_content_publish — publicar. Obrigatória.
  • instagram_business_manage_insights — métricas. Usada depois, para ajustar horários.
  • manage_comments e manage_messages — opcionais, pode deixar marcadas.

Não se preocupe em desmarcar as opcionais: o token do painel vem com o conjunto padrão e permissão sobrando não atrapalha.

!

Se aparecer "Função de desenvolvedor é insuficiente"

O erro mais comum do Passo 3. A mensagem engana.

Ela não fala do seu papel no app — fala do papel da conta do Instagram que o navegador mandou. Ser dono da @jamesolaya.es e ser admin do app são duas identidades separadas, e enquanto o app está em desenvolvimento só quem tem papel nele pode autorizar.

As três causas, em ordem de frequência:

  1. Sessão errada no navegador. É quase sempre isto. Refaça o Passo 3 em janela anônima, com só a conta certa logada.
  2. A conta não foi convidada como testadora. No painel: Funções do app → Funções → seção de testadores do Instagram → adicione jamesolaya.es. E o convite fica pendente até ser aceito do lado do Instagram, não do painel — é aqui que quase todo mundo empaca: instagram.com/accounts/manage_access → aba Convites de testador → Aceitar.
  3. A conta do Instagram não está ligada à sua conta Meta. Vincule na Central de Contas, pelo app do Instagram: Configurações → Central de Contas → Contas → Adicionar contas, entrando com a mesma conta Meta que criou o app.
Como saber qual é a sua: olhe o @ na tela de consentimento do pop-up. Se não for jamesolaya.es, é a causa 1. Se for a conta certa e ainda falhar, é a 2 ou a 3.
4

Pegar o INSTAGRAM_USER_ID

Um comando no terminal

Troque SEU_TOKEN pelo que você copiou:

curl -s "https://graph.instagram.com/v26.0/me?fields=user_id,username&access_token=SEU_TOKEN"

Resposta esperada:

{"user_id": "178414...", "username": "jamesolaya.es"}
Use o campo user_id, não o campo id. São números diferentes, e o id não funciona para publicar. E confira o username: se vier outro, você logou na conta errada no Passo 3 — volte e refaça em janela anônima.
5

Guardar as credenciais

Local agora; no GitHub quando o repositório existir

cd ~/PROJETOS_DEV/jamesolaya-es-social cp .env.example .env

Abra o .env e preencha as duas linhas. Ele já está no .gitignore.

INSTAGRAM_USER_ID=178414... INSTAGRAM_ACCESS_TOKEN=IGAA...
Nunca coloque a chave da Anthropic nos secrets do GitHub. O runner publica legendas já congeladas na fila e nunca chama IA. Chave que não precisa estar lá é superfície de ataque de graça.

Quando o repositório existir, os mesmos valores viram Settings → Secrets and variables → Actions → aba Secrets. Na aba Variables: PUBLISH_ENABLED = false por enquanto.

6

Validar

O script diz, linha a linha, se está tudo certo. Não publica nada.

uv run python scripts/validar_conta.py

Ele confere cinco coisas: se o token é válido e aponta para a conta certa, se o user_id bate, se a permissão de publicar está ativa, quanto resta da cota de 24 horas, e se a trava PUBLISH_ENABLED está desligada.

Quando passar, me avisa. Aí eu conecto a ingestão da fila e a gente faz o primeiro post de teste, disparado à mão e conferido no app antes de ligar o cron.

Renovação: a parte que mata o sistema em silêncio

O token vale 60 dias e, se expirar, não há como recuperá-lo — só gerar outro pelo painel, à mão. Sem automação de renovação, o robô para de publicar sozinho e ninguém percebe até alguém abrir o perfil.

Duas formas de renovar, ambas válidas:

  • Pelo painel: Instagram → Configuração da API → Gerar token. O novo vale imediatamente.
  • Pela API, com um token que tenha pelo menos 24h de vida e ainda não tenha expirado:
curl -s "https://graph.instagram.com/refresh_access_token?grant_type=ig_refresh_token&access_token=SEU_TOKEN"

O projeto já tem isso implementado e um cron mensal que renova sozinho e atualiza o secret do GitHub. Para funcionar ele precisa de um SECRETS_PAT — um token fine-grained do GitHub com Secrets: Read and write. O doctor avisa quando faltam menos de 14 dias.
